# OMNI conformance corpus (suite 0)

Generated by `omni-conformance generate`. Do not edit by hand — every
case is produced from source in `reference/omni-conformance/src/cases.rs`,
next to the rule it exercises and the reason it exists.

```console
$ omni-conformance run conformance/ --impl ./my-reader
```

The runner judges an implementation by its exit code, so any
implementation in any language can be tested without linking against
this one.

| Expectation | Exit code | Meaning |
|---|---|---|
| `accept` | 0 | The file is valid and must load and validate cleanly. |
| `reject` | 1 | The file violates a normative rule and must be refused. |
| `degrade` | 0 or 3 | The file uses something this version does not define. It must still open, list, copy and verify. Rejecting it is a conformance failure. |

The `degrade` row is the one that matters most. It is the difference
between a format that can be extended and one that cannot, and it is
the case implementations most often get wrong — refusing a whole file
because one part of it is from the future.
